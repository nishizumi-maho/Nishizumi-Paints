# Nishizumi Paints 7.3.2

Release date: 2026-08-13

## Updates install themselves now

Until 7.3.1 an update check ended at a dialog offering to open the GitHub release page. From 7.3.2 the app can finish the job: it downloads the installer, verifies it, runs it silently, and reopens on the new version.

The update notice now has three answers instead of two:

- **Yes** — download and install now.
- **No** — open the release page, the old behaviour.
- **Cancel** — not now, ask again on the next check.

Turn on **Install updates automatically** on the General tab (off by default) and the app skips the dialog entirely: the next verified release is installed without asking. **Check for updates automatically** still controls whether the app looks for releases at all, every 6 hours as before.

An **Install update** button sits next to **Check updates** for installing on demand.

## What happens during an install

1. The installer asset is downloaded to `%APPDATA%\NishizumiPaints\updates`, with progress shown in the update status line.
2. Its SHA-256 is compared against the digest published with the release.
3. A one-line script is started detached, the app shuts down completely so the installer can replace its own files, and the installer runs with `/SILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS`.
4. On success the new version is started; on failure the app stays on the old version and the Inno Setup log is kept at `%APPDATA%\NishizumiPaints\updates\install.log`.

The installer keeps installing per-user into `%LOCALAPPDATA%\Programs\Nishizumi Paints`, so no UAC prompt appears and your settings, catalog cache, and paints are untouched. Older downloads in the update folder are cleared each time.

## The file is verified before it is executed

The update path ends in running an `.exe`, so every step refuses by default and only proceeds on an exact match:

- The download URL, and every redirect hop, must be HTTPS on `github.com`, `api.github.com`, `objects.githubusercontent.com`, or `release-assets.githubusercontent.com`. A redirect anywhere else aborts the download.
- The release must publish a SHA-256 digest — GitHub's own `digest` field on the asset, or a `<sha256>  NishizumiPaints-Setup-<version>.exe` line in the release notes. **Without a digest the app will not auto-install**; it opens the release page instead.
- The digest is computed while streaming and compared before the file is kept. A mismatch deletes the download.
- The asset name must be a plain `.exe` filename with no path separators, and the download is capped at 400 MB.

Anything that fails leaves you exactly where 7.3.1 left you: a notice, and the release page.

## Limits

- Automatic installation only works in the packaged Windows `.exe`. Running from source reports the update and opens the release page, because there is nothing for an installer to replace.
- The headless service does not check for updates; that was already the case in 7.3.1 and has not changed.

## Validation

- 26 new tests cover the host allowlist (including lookalike hosts such as `github.com.evil.test` and plain HTTP), digest parsing from both the API field and three release-note layouts, a digest published for a different asset, download success, progress reporting, digest mismatch, redirect off GitHub, missing digest, oversized and unbounded bodies, unsafe asset filenames, HTTP errors, the generated install script, and the update folder cleanup.
- Full suite: 83 tests, all passing.
