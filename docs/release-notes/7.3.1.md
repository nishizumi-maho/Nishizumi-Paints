# Nishizumi Paints 7.3.1

Release date: 2026-08-12

## The automatic car catalog works again

Trading Paints redesigned `https://www.tradingpaints.com/cartemplates`. The old page put the vehicle ID in the element id of each template block (`<div id="car_264">`); the new page does not carry the vehicle ID at all. Nishizumi Paints read that ID to bridge an iRacing paint directory to a Trading Paints vehicle, so on the redesigned page the catalog parsed **zero cars**.

The catalog is now rebuilt from two pages instead of one:

- `https://www.tradingpaints.com/cartemplates` supplies the vehicle name and the exact `Documents/iRacing/paint/...` directory.
- `https://www.tradingpaints.com/showroom` supplies the vehicle ID and the Oval, Road, or Driver category, read from the `/showroom/{Category}/{mid}/{slug}` vehicle links.

The two lists are joined on the vehicle name. Against the live pages this rebuilds 181 car directories from 184 templates and 174 showroom vehicles.

### What this restores

Public showroom downloads, collections, Member ID tools, Team tools, the RandomPool, and the car selectors in the Showroom tab.

Normal session downloads were **never** affected by this bug. They use the paint directory reported by iRacing and Trading Paints, not the catalog.

## Correct vehicle categories

Every vehicle used to be filed as `Road`, because the template page never published a category. The showroom index does, so vehicles are now filed under their real Oval, Road, or Driver category and the showroom links the app builds point at the right page.

## Grouped vehicles

Trading Paints groups several iRacing directories under one showroom vehicle: a single `Dirt Sprint Cars` vehicle covers the 305, 360, and 410 templates. When a template name has no exact match in the showroom index, the directory segments join the name so the *most specific* vehicle wins, and an ambiguous match is dropped instead of guessed. Superspeedway variants keep resolving to their own vehicle ID, so `Gen 4 Chevrolet Monte Carlo - 2003` and its `SS` variant stay distinct.

One legacy template (`[Legacy] Gen 4 Cup`) has no showroom vehicle at all on Trading Paints and is therefore left out of the catalog. Only public showroom features are affected for that car; downloading paints for it still works.

## The catalog survives the next redesign

The catalog that was built last is now saved to `%APPDATA%\NishizumiPaints\.nishizumi_tp_car_identity.json` and reused for up to 30 days whenever Trading Paints is unreachable or changes its page layout again. Instead of starting with an empty catalog, the app starts with the last known-good one and says so in the log.

## Other fixes

- Failures to install an iRacing UI preview file are now reported in the log with the reason instead of being discarded silently at debug level.
- The Showroom tab status line lists both live sources the catalog is built from.

## Validation

- 8 new regression tests cover the two-page join, both nested markup shapes of the directory cell, showroom links that are not vehicle links, grouped-vehicle selection, and the on-disk catalog cache (round trip, empty/corrupt/expired/foreign-version rejection, refresh persistence, and the offline fallback).
- Full suite: 57 tests, all passing.
- The parsers were also run against the live Trading Paints pages, not only against fixtures.
