# Nishizumi Paints 7.3.0

Release date: 2026-08-11

## Always-on iRacing UI car previews

The iRacing UI renders a car in its 3D viewer (`My Content > Cars > vehicle`) from the same custom paint files the sim uses:

- `Documents\iRacing\paint\<car directory>\car_<customer id>.tga`
- `car_num_<customer id>.tga`, `car_spec_<customer id>.mip`, `decal_<customer id>.tga`
- `Documents\iRacing\paint\helmet_<customer id>.tga` and `suit_<customer id>.tga`

Until now those files only existed while a live session was running, so the previews were correct by accident. Nishizumi Paints now owns them:

- Your own Trading Paints assets are mirrored into `%APPDATA%\Nishizumi-Paints\UiPreviewCache`.
- The mirror is installed into the iRacing paint folder whenever iRacing is idle and re-installed right after every session cleanup.
- The iRacing UI reloads the viewer as soon as those files change, so the preview follows your active Trading Paints livery.

## Reliability details

- Team paints are excluded on purpose. They land on `car_team_<team id>.tga`, which the UI viewer never reads.
- Superspeedway variants are excluded. The viewer always renders the standard paint.
- The freshest manifest asset of each type wins, matching the session pipeline's selection rules.
- Nothing is touched while a session is being processed, so the previews never compete with the live paint pipeline.
- Session cleanup can no longer delete preview files, and any file that is deleted or overwritten by something else is restored on the next idle pass.
- Re-installs are signature checked, so the steady-state cost is one `stat` per asset and no repeated copying.
- Paints removed from your Trading Paints account stop being previewed and their files are removed from the iRacing paint folder.
- Turning the feature off removes only the files the app itself installed. Hand-made and third-party paints are left alone.

## Customer ID detection

The UI viewer only ever renders `car_<customer id>.tga`, so the wrong ID means silently empty previews. The ID is resolved in this order:

1. Manual override in the General tab.
2. The live iRacing session.
3. The Trading Paints member ID from the Showroom tab.
4. The AI roster member ID from the AI tab.
5. A confirmed Trading Paints login.
6. The ID remembered from a previous run.

The last one means the previews keep working before iRacing has been started even once in the current session.

## Custom Number paints

iRacing only uses `car_num_<customer id>.tga` when "Hide car numbers" is enabled in Settings > Graphics. The app reads `hideCarNum` from `Documents\iRacing\app.ini` read-only and reports the mismatch in the status line. It never edits iRacing settings.

## Controls

- General tab and Easy screen: `Always show my paints in the iRacing UI car previews`, a re-check interval, a customer ID override, and `Sync previews now`.
- Command line: `--no-ui-previews`.
- Headless control: the `sync_ui_previews` command, plus `ui_preview_*` fields in the `status` response.

## Validation

- 38 new regression tests cover manifest selection, customer ID resolution, `app.ini` parsing, install/restore/skip behavior, cleanup protection, sync pruning, customer ID changes, partial failures, and the service scheduling rules.
- CI now installs the runtime dependencies and runs the full unit test suite on every push and pull request.
